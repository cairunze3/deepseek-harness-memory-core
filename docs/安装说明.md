# 记忆插件安装说明（给同事）

> 包名：`vanwork-memory-core` · 版本 `0.8.1` · 适用 **DSH 0.2.0-rc.2**（当前 VanWork 桌面版）
> 你会拿到：`vanwork-memory-core-0.8.1.tgz` 和本说明；同目录还有技术文档与 README，不看也能装。

---

## 0. 它会给你什么

装好之后，你的 AI 会：

1. **每轮带一点核心记忆** —— 默认预取 2 条（global / user / 当前项目 key）；其余按需检索，不是全量目录。
2. **能主动查** —— 10 个 `mem_*` 工具：`mem_search` / `mem_read` / `mem_write` / `mem_extract` / `mem_health` / `mem_query_log` / `mem_global` / `mem_audit` / `mem_consolidate` / `mem_reindex`。
3. **改结论不抹历史** —— 用「取代」而不是删除，旧结论留档可回溯。
4. **设置页多一个「记忆管理」** —— 可以手改全局记忆、看当前记忆状态。

记忆仍然存在你本机的 Markdown 文件里（`$DSH_HOME\memories`），**不联网、不上传、零第三方依赖**。

## 1. 安装（3 分钟）

### 第 1 步：把 tgz 放到一个固定目录

例如 `D:\dsh-plugins\vanwork-memory-core-0.8.1.tgz`。

> ⚠️ **别放在下载目录然后删掉。** 安装器会把它记为 `file:` 依赖，以后重装/修复时找不到文件会报错。

### 第 2 步：安装（二选一）

**方式 A：图形界面（推荐先试）**

1. 打开 VanWork → 左侧边栏「**插件**」页；
2. 找到「安装 / 添加组合包」的输入框；
3. 粘贴 tgz 的**完整绝对路径**（例：`D:\dsh-plugins\vanwork-memory-core-0.8.1.tgz`），确认安装；
4. 装完确认这个组合包处于**已启用**状态。

**方式 B：命令行（界面里找不到入口时用）**

```powershell
# 如果 dsh 已在 PATH：
dsh plugin --profile web add "D:\dsh-plugins\vanwork-memory-core-0.8.1.tgz"

# 如果提示找不到 dsh（VanWork 默认装在当前用户目录）：
& "$env:LOCALAPPDATA\Programs\VanWork\resources\runtime\node.exe" `
  "$env:LOCALAPPDATA\Programs\VanWork\resources\runtime\app\node_modules\@deepseek-ai\dsh\lib\bin.js" `
  plugin --profile web add "D:\dsh-plugins\vanwork-memory-core-0.8.1.tgz"
```

> 如果 VanWork 装在别的盘，把上面两处 `$env:LOCALAPPDATA\Programs\VanWork` 换成你的实际安装目录。

### 第 3 步：**完全退出** VanWork 再启动

插件在宿主启动时装载。点窗口关闭不算完全退出——用托盘菜单退出，或任务管理器确认 `VanWork.exe` 已结束，然后重新打开。

## 2. 装好了吗？（三条自检）

| # | 怎么做 | 应该看到 |
|---|---|---|
| ① | 新开一个会话，问：「你现在有哪些 `mem_` 开头的工具？」 | 列出 **10 个**：`mem_search` / `mem_read` / `mem_write` / `mem_extract` / `mem_health` / `mem_query_log` / `mem_global` / `mem_audit` / `mem_consolidate` / `mem_reindex` |
| ② | 设置 → 找「**记忆管理**」 | 有这一节，能点「修改记忆」 |
| ③ | 让 AI 执行 `mem_audit` | 逐项 ✓（`load.patch`、`store.canon`、`write.path` 等），不应出现「未装载」；`[tools.self]` 应显示 10 个 |

三条都过 = 装好了。只看得到工具、没有「记忆管理」也不影响使用——那说明当前上下文没有 Web 服务，界面会自动跳过（记忆与工具照常）。

> 0.8.1 的 pointer 预取会显示 **2 条核心记忆**（global/user/当前项目 key），不是全量目录；口令/密钥类条目不自动预取，仍可显式 `mem_read`。

## 3. 推荐配置（可选，但建议做一次）

当前 VanWork 默认可能还带着旧的 `dsh-memory-evolve`。如果两个都装着，同一批记忆可能被注入两遍（不影响正确性，只浪费上下文）。分工办法：

打开 `%APPDATA%\VanWork\accounts\<你的账号>\dsh-home\profiles\web\cordis.patch.yml`，在**文件末尾追加**（注意是顶层覆盖，不要写 `insert`）：

```yaml
- id: vanwork-memory-core
  config:
    injectExclude: ['global:memory', 'global:user', 'project:key']
    exclusiveWritePath: true
    # pointer 预取条数；0 = 关闭，回到“不预载任何条目”
    pointerRecallTopN: 2
    # 队列候选被召回几次才转正
    queuePromoteMinHits: 2
    # pointer（默认）/ index / auto
    indexMode: pointer
```

含义：旧插件负责「重要小集合」（全局 MEMORY / 全局 USER / 项目 KEY），新插件负责**每日日志与项目笔记**——这两类旧插件根本不注入，所以不重叠。再把 `exclusiveWritePath` 设为 `true`，等于声明「以后只用 `mem_*` 写记忆」，`mem_audit` 的判定会变成「写入编排已归一」。

> 找不到账号目录？在会话里让 AI 执行 `mem_audit`，输出里会打印它实际读到的那个 patch 文件路径。
> 改完同样需要**重启**生效。

**另一种选择**：如果你不需要旧插件那套注入，保持默认 `injectExclude: []` 也行——新插件自己覆盖全部轨道。

## 4. 卸载 / 临时关闭

```powershell
# 卸载
dsh plugin --profile web remove vanwork-memory-core

# 临时关闭（不用卸载）：在 profile 的 cordis.patch.yml 里加
# - id: vanwork-memory-core
#   disabled: true
```

记忆文件**不会**因为卸载而删除（它们在 `$DSH_HOME\memories`，是纯 Markdown）。

## 5. 常见问题

| 现象 | 原因 / 怎么处理 |
|---|---|
| 装完没有任何 `mem_*` 工具 | 没重启，或组合包没启用。先彻底退出再启动；还不行去「插件」页确认已启用 |
| 注入里出现 `<memory_index status="degraded">记忆索引暂不可用…` | 索引出错，**记忆文件本身完好**。让 AI 执行 `mem_reindex(force=true)`，再看 `mem_health` |
| 提示「最近若干轮没有写入记忆」 | 正常提醒（连续 5 轮没写才出现）。随便写一条 `daily` 就归零 |
| 设置里没有「记忆管理」 | 当前上下文没有 Web 服务，界面自动跳过；不影响记忆与工具 |
| 面板保存提示「被改过了」 | 你编辑期间这份记忆被别处更新了（防覆盖）。重新打开面板再改 |
| 启动日志有一行 `ExperimentalWarning: SQLite` | Node 内建 SQLite 的实验性提示，不影响使用。不想看到就在配置里加 `backend: 'json'` |
| 担心它联网 | 默认零联网：向量检索默认关、云端分层只做判定不发请求、Git 只读本地 remote |
